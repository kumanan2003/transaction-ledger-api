# Transaction Ledger API — Assumptions

1. **Account creation:** Every new account starts with a balance of zero. The client cannot choose the initial balance.

2. **Currency representation:** The API stores monetary values as integer paise to avoid floating-point rounding errors. For example, ₹100.50 is represented as `10050`.

3. **Transaction types:** Only `credit` and `debit` transactions are supported.

4. **Positive amounts:** Transaction amounts must be positive safe integers. Zero, negative values, decimals, and unsafe integers are rejected.

5. **Sufficient balance:** A debit transaction is accepted only when the account has enough funds.

6. **Unique references:** A `reference_id` must be unique within an account. The same reference may be used by a different account.

7. **Atomicity:** Updating the account balance and inserting its transaction record must succeed together or be rolled back together. MongoDB transaction support is required.

8. **Transaction history:** Transactions are returned newest first. Optional type filtering and pagination are supported.

9. **Immutable transaction records:** Existing transaction details are not intended to be edited after creation.

10. **Timestamps:** Account and transaction creation timestamps are generated by the server.

11. **Authentication:** Unless implemented separately, authentication and authorization are outside the scope of this project.

12. **Deployment:** The application is configured for local development using environment variables. Production deployment and production-grade security configuration are outside the scope unless explicitly implemented.
